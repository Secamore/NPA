# Public deployment

The app is a Streamlit web application. A Docker image runs it on the port supplied by
the hosting platform, and the app is usable from current desktop and mobile browsers.
No separate Windows, macOS, or Android build is needed.

## Deploy on Render

1. Push the project to a private GitHub repository. The local SQLite database is
   currently tracked in this workspace; do not make the repository public unless that
   database is removed from Git and its history has been checked for sensitive data.
   Keep passwords, invite codes, and `.env` files out of the repository.
2. In Render, create a Blueprint from that repository and apply the included
   `render.yaml`. The web service uses Docker, health-checks Streamlit, and mounts a
   persistent disk at `/data` for the SQLite database and saved branding assets.
3. In the Render service environment settings, set `NPA_MANAGER_PASSWORD` to a strong,
   unique secret. Do not put this value in source control.
4. `NPA_MANAGER_INVITE` is generated by the Blueprint. Use it only for authorized
   manager registration; remove or rotate it after initial setup if more manager
   self-registration is not required.
5. Wait for the service to deploy, then open its `onrender.com` URL over HTTPS. Share
   that URL with users; they can open it in a modern browser on Windows, macOS, Android,
   or other supported devices.

Staff and company users can register from the public page, but their accounts require
approval. Manager registration requires the invite code. Only share the manager invite
with trusted administrators.

The local SQLite database and Python environment are excluded from the Docker build
context. The persistent `/data` disk must remain attached to avoid losing accounts,
submissions, and audit history on restart.
